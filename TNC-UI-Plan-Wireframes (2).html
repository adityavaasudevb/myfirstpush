TNC Insurance Platform — UI Journey & Wireframes

v3 · Prepared for trainer review · Scope: Angular SPA behind YARP gateway · 14 screens · Consistent with Design Doc v3.0 (rev. 30-Sep-2026) — Tier A/B model, straight-through binding, simulated payments, single document link, four-field verification · Password reset intentionally absent (Appendix D, item D1).

1. Design Principles Applied

  • The sign-in page is a chooser, not a form: two info cards (Company / Surveyor), each with ONE button leading to that role's own auth page. Admins get a small text link.
  • One shared login component, three doors: each auth page toggles Log In ↔ Sign Up; all login forms call the same POST /api/auth/login; the JWT role claim routes the user (/company, /surveyor, /admin).
  • Registration is split because data differs — Company (email, password) vs Surveyor (7 fields incl. IRDAI licence number + validity date).
  • Detail ≠ page: policy/claim/report detail are expanding table rows; small decisions are modals (renewal compare, reject reason); related views are tabs.
  • After login, every role screen carries that role's navbar (brand, section links, user chip, Logout) — enforced by route guards.
  • Payments are a moment, not a page: paying a policy premium is a simulated, always-succeeds click on the Policies row → success toast → status flips Active (trainer decision; Design Doc FR6).
  • Toasts carry server messages: register success, "pending admin approval", rejected login (echoes the admin's reason), 403/409/410 messages.

2. UI Journeys

PUBLIC
Landing / About (info only)→ Sign-in chooser (2 cards)→ /auth/company or /auth/surveyor→ login (any of 3 entries)→ Route by role claim
COMPANY
Login→ First login? → Create Company Profile (forced)→ Dashboard→ Quote (₹+$, 7-day expiry) → Apply→ Policy Pending→ Pay (simulated) → Active→ File Claim → preliminary decision→ Track claim → Paid→ Renew in 30-day window → pay to accept / cancel to decline
SURVEYOR
Register (7 fields)→ 403 PENDING → toast/ 403 REJECTED → toast w/ admin reason→ Approved → login OK→ Queue → Claim (atomic pickup)→ Verify 4 fields → submit report
ADMIN (seeded)
Login→ Dashboard (5 metrics + attention list)→ Approvals: surveyor approve / reject+reason→ Claim Decisions: review report → approve → Paid / reject (override note)
