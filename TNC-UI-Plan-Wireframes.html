TNC Insurance Platform — UI Journey & Wireframes

v1 · Prepared for trainer review · Scope: Angular 19 SPA behind YARP gateway · 14 screens total (no full-page detail views — detail lives in expanding rows / modals / tabs) · Consistent with Design Doc v3.0 FRs; password reset intentionally absent (Appendix D, item D1).

1. Design Principles Applied

  • One login, three doors: a single email+password login (same POST /api/auth/login) behind Company / Surveyor / Admin entries; the JWT role claim routes the user to their section.
  • Registration is split because data differs — Company (email, password) vs Surveyor (7 fields incl. IRDAI licence no. + validity) — hence the two-box sign-in page (HackerRank pattern).
  • Detail ≠ page: policy detail, claim detail, and admin's report view are expanding table rows. Small decisions are modals (renewal compare, reject reasons). Related views are tabs.
  • Role-based navigation enforced by route guards; URLs are deep-linkable per role area (/company/…, /surveyor/…, /admin/…).
  • Toasts carry server messages: register success, "pending admin approval", rejected login (shows the admin's recorded reason), 403 messages (SURVEYOR_PENDING_APPROVAL etc.).
  • Every table that lists things gets search + filter + sort once (demonstrated fully on Policies; pattern reused on Claims / Queue).

2. UI Journeys

PUBLIC
Landing / About→ Sign-In page (two boxes)→ Company OR Surveyor sign-up→ Toast: registered→ Login (any of 3 entries)→ Route by role
COMPANY
Login→ First login? → Create Company Profile (forced)→ Dashboard→ Quote → comparison → Apply→ Policy Pending→ Buy Now → payment success → Active→ File Claim → preliminary decision→ Track / resubmit / get paid→ Renew within 30-day window
SURVEYOR
Register (7 fields)→ 403 PENDING → toast "awaiting approval"/ 403 REJECTED → toast with admin's reason→ Approved → login OK→ Queue tab → Claim (atomic pickup)→ Investigation: verify fields → submit report
ADMIN (seeded)
Login→ Dashboard (stats)→ Approvals: surveyor approve / reject+reason↔ Approvals: claim payout gates→ Claim Decisions: approve / reject (override note)→ Payments: mark succeeded / failed
