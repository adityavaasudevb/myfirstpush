TNC Insurance Platform — UI Journey & Wireframes

v2 · Prepared for trainer review · Scope: Angular SPA behind YARP gateway · 14 screens (no full-page detail views — detail lives in expanding rows / modals / tabs) · Consistent with Design Doc v3.0 — including its tier/pricing values · Password reset intentionally absent (Appendix D, item D1).

1. Design Principles Applied

  • The sign-in page is a chooser, not a form: two info cards (Company / Surveyor), each with ONE button leading to that role's own auth page (HackerRank pattern). Admins get a small text link.
  • One shared login component, three doors: each auth page toggles Log In ↔ Sign Up; all login forms call the same POST /api/auth/login; the JWT role claim routes the user (/company, /surveyor, /admin).
  • Registration is split because data differs — Company (email, password) vs Surveyor (7 fields incl. IRDAI licence number + validity date).
  • Detail ≠ page: policy detail, claim detail, and admin's report view are expanding table rows. Small decisions are modals (renewal compare, reject reason). Related views are tabs.
  • After login, every screen of that role carries the same role navbar (brand, section links, user identity chip, Logout) — enforced by route guards.
  • Toasts carry server messages: register success, "pending admin approval", rejected-surveyour login (echoes the admin's recorded reason), 403 messages (SURVEYOR_PENDING_APPROVAL etc.).
  • Every list gets search + filter + sort once (demonstrated fully on Policies; pattern reused on Claims / Queue).

2. UI Journeys

PUBLIC
Landing / About (info only)→ Sign-In chooser (2 cards)→ /auth/company or /auth/surveyor→ register → toast/ login (any of 3 entries)→ Route by role claim
COMPANY
Login→ First login? → Create Company Profile (forced)→ Dashboard→ Quote → tier comparison → Apply→ Policy Pending→ Pay → payment success → Active→ File Claim → preliminary decision→ Track / resubmit / get paid→ Renew within 30-day window
SURVEYOR
Register (7 fields)→ 403 PENDING → toast "awaiting approval"/ 403 REJECTED → toast shows admin's reason→ Approved → login OK→ Queue tab → Claim (atomic pickup)→ Investigation: verify fields → submit report
ADMIN (seeded)
Login→ Dashboard (stats)→ Approvals: surveyor approve / reject+reason↔ Approvals: claim payout gates→ Claim Decisions: approve / reject (override note)→ Payments: mark succeeded / failed

  1. A4 page → demo POST …/simulate in Swagger. FR intact.
  2. Quote history list UI (C2 collapsible) → keep API + tests; hide UI.
  3. C7 view → merge into Dashboard tab (already annotated).
